# Narrated Demo Video

把视频当作可重建的工程：录屏、旁白、配乐、字幕、时间线分别保存。用户改一句旁白或调整音乐时，只重做受影响的部分。

## 开始前

1. 从上下文确认观众、平台、时长、横竖屏、已有素材、期望语气和交付格式。没有关键约束时可以先写脚本；不要为了常规剪辑选择反复询问。
2. 查找已有工程和最新成片，先读其时间线，不覆盖唯一副本。修改任务先判断是画面、字幕、声音还是片尾变化。
3. 找到 Python 3.10+ 和带 `libx264`、`libass` 的 FFmpeg；通过 PATH 或 `FFMPEG_BIN` 配置。`FFPROBE_BIN` 可选。不要把本机绝对路径写进可迁移配置。
4. 使用当前环境允许的工具。此 skill 不提供浏览器权限，也不要求某种 harness、完整 CDP 或绕过站点限制。录屏接入见 [recording.md](references/recording.md)。

## 制作顺序

### 1. 先完成可拍的脚本

做一张分镜表：时间段、要说的话、真实画面、声音、屏幕文案。短宣传片可以用“有趣结果 → 怎么来的 → 两三个亮点 → 入口”组织，但服从用户要的风格。字幕与标题各司其职，不要把说明书塞满画面。

先写每段约 5–12 秒的旁白，开场和笑点留原声/停顿。中文每秒约 3–5 字只用于初稿估算，最终时长以合成结果为准。功能、入口和效果必须来自实际产品或用户提供的信息，不夸大尚未实现的功能。

### 2. 录真实操作，保留可剪余量

按照分镜逐条拍摄。录制与测试是不同任务：尊重用户是否允许自动试玩、是否希望自己测试。拍摄用隔离存档、测试账号或单独浏览器配置，先确认不会污染正式数据；不同域名只有在存储隔离确实适用时才有用。

每个镜头保留前后余量。存原始视频；如果工具只能提供带时间戳的帧，保存 `frames.json`，用 `scripts/frames_to_video.py` 按真实时间间隔转视频。帧截图没有音轨，必须单独录音或明确安排配音/音效，不能宣称保留了原声。宣传美术与实际游玩镜头不要混淆。

### 3. 分段配音后再锁定时间线

仅把用户授权用于配音的文本发给用户指定服务。对于 JSON 输入、WAV 输出的 Mambo 兼容接口，使用 `scripts/tts_client.py`；其他服务写一个薄适配层，保留同样的分段 WAV 产物。服务地址和凭证从环境变量读取。

`401/403/404` 不是继续猜地址或绕过认证的理由：停止该请求，告诉用户实际状态，并继续能独立完成的画面工作。用户告知服务恢复后可重试。脚本仅对临时错误做有限退避，保存已成功的分段缓存。

听取关键配音和句尾，核对数字、专有名词、笑点。按 WAV 实际时长安排镜头；声音放不下时先延长镜头/缩短文案/重配，再考虑轻微加速。脚本超过默认 1.2 倍即报错，绝不把半句话截断后当作成功。

### 4. 分层剪辑、字幕与混音

按照 [project-format.md](references/project-format.md) 创建 `project.json`，参考 [example-project.json](references/example-project.json)。所有素材路径相对该文件。运行：

```sh
python /path/to/narrated-demo-video/scripts/render_video.py render --project project.json --out output/v1
```

产物包括静音画面 `picture.mp4`、无字幕版 `clean.mp4`、字幕版 `final.mp4`、ASS/SRT、旁白/音乐/音效分轨、混音及构建报告。FFmpeg 以参数数组调用，不拼 shell 命令。

明确旁白、音乐、原声与音效各自的增益。用户说“音乐 20%”时理解为该轨乘 0.20，不意味着响度一定合适。听混音再调；笑点留声音空间。混音使用 `amix normalize=0` 避免输入条数改变各轨增益，再用限制器保护峰值；不是把所有声音盲目叠满。

字幕按实际配音安排，一屏一两句、足够大、避开关键 UI。本脚本按时间线输出字幕，不做强制对齐；按文字长度估算时间只能称为近似字幕。需要逐字精确时另接用户可用的转录/对齐工具。

### 5. 验证并交付

检查成片时长、分辨率、音轨、字幕、开头/转场/结尾帧；听开头、中段、最密集混音和句尾。不要仅凭进程退出码宣称观感通过。如果无法试听或查看，明确哪些项目尚未验证。

把可播放成片、时间线、字幕、分轨和必要素材放在独立版本目录。用户需要源工程时再整理素材包；不要无意打包服务凭证、浏览器状态、缓存日志或无关素材。公开发布和发消息按用户授权范围执行；完成导出不等于已经发布。

## 修改已有视频

- **只调声音**：修改音轨配置，使用 `remix --project project.json --out output/v1`。脚本会核验画面/字幕签名并复制已编码视频流；签名变化会拒绝，防止悄悄沿用旧画面。先复制版本目录或保留旧成片。
- **改一句旁白**：重生成该段，核对时长与字幕，复用其余音轨和镜头。
- **改片尾**：保留前半段时间线，仅替换末尾镜头、旁白和字幕，处理 BGM 收尾；不要把旧片尾旁白留下来双声道打架。
- **画面/字幕变更**：重新 `render`，脚本按素材内容及参数签名复用单镜头缓存；不要只用“文件存在”判断缓存有效。

进一步的剪辑判断、交付检查和故障处理见 [editing.md](references/editing.md)。脚本环境自检可运行 `python scripts/smoke_test.py`；它使用合成色块和音调，不访问用户游戏或真实 TTS 服务。
