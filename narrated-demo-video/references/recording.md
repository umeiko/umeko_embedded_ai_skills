# 录屏适配：与 agent 工具解耦

这套工作流曾用浏览器操作工具完成实际游戏操作，用 Python/FFmpeg 转换录制帧，再单独混入旁白、角色音效和 BGM。真正可移植的是输入/输出约定，不是某个产品的工具调用名称。

## 选择当前可用的录制方式

优先使用当前 agent 已获准的原生录屏工具，输出 MP4/MKV/WebM。OBS、操作系统录屏、浏览器工具的录制能力都可以；先阅读工具自己的文档，不假定存在 `startRecording()` 等接口。

若允许的浏览器工具提供帧流，则保存图片和时间戳。若允许使用 CDP，可由适配器消费浏览器 screencast 帧事件并记录其时间戳，但这不是本 skill 要求的能力，也不能借此绕过工具权限。收到的帧应及时保存/排队并依照提供方协议 ACK；写盘堵塞会造成丢帧。严禁用高速截图循环伪称高帧率原生录屏。

如果只提供离散截图，适合定格介绍/慢推镜头，不足以重建快速玩法；应请用户录制或选择支持录屏的工具。导出 30 fps 只代表容器帧率，不证明原始捕获每秒有 30 张独立画面。

## 录制计划

记录每条素材的来源、内容、窗口大小、是否含原声、可用片段、敏感信息和是否为真实操作。每条镜头一般 6–15 秒、前后各留约一秒。先录主线，再录几个补镜；不用一次操纵完整两分钟内容。

展示账号、订单、终端或管理界面之前检查个人信息。涉及真实支付、删除、发送消息、公开发布的操作不应为了拍摄顺手执行；使用用户授权的演示环境或停在确认之前。

切换窗口导致丢失焦点、录屏尺寸变化、软件弹窗和迟滞要记录到素材备注，不把它们误认为产品本身的表现。旁白可后配，不必边说边操作。

## 帧目录约定

```text
raw/take-01/
  frames.json
  000000.jpg
  000001.jpg
  ...
```

```json
[
  {"file": "000000.jpg", "time": 1000.000},
  {"file": "000001.jpg", "time": 1000.040},
  {"file": "000002.jpg", "time": 1000.091}
]
```

`time` 为秒，来自同一时钟并严格递增；绝对或相对时间均可。最后一帧默认占 `1/fps` 秒。输出时长是末帧时间减首帧时间再加最后一帧时长。图片路径相对 `frames.json`。不要以文件创建时间冒充精确捕获时间。

```sh
python scripts/frames_to_video.py --frames raw/take-01/frames.json --output footage/take-01.mp4 --width 1920 --height 1080 --fps 30
```

转换器使用 ffconcat duration，并输出恒定帧率、等比例缩放、居中补边的 H.264 视频。它不会生成原声。

## 原声

确认录屏文件确实含音频流，而不是仅凭扩展名判断。系统声音采集是否可用取决于工具和权限。无原声时可使用独立音效素材；不要混入未在项目清单登记的音频。

有原声的素材可同时作为 `clips[].source` 和 `audio[].source`，给后者安排同样的 `in`/`start`/`duration`。只在需要保留原声的片段开轨，避免游戏 BGM 与后期 BGM 重叠。
